# SEO and visitor measurement audit — 27 October 2026

Checked the repository and live HTTP responses from aptechagency.com and www.aptechagency.com. This is a technical audit, not a Search Console ranking or traffic report. No Search Console, Analytics, backlink or conversion data was available.

## Confirmed findings and fixes

| Finding | Evidence | Change |
| --- | --- | --- |
| Visitor counts missed public pages | Tracking lived inside LandingPage, with a single tab-session flag; direct blog entries and other public shells never recorded a website visit. | One shared public-route tracker records navigation across public pages. Known bots and private portal routes are excluded. |
| Daily totals used the server timezone | getLandingVisitorStats used Date.setHours rather than the business timezone. | Daily and monthly boundaries use Asia/Dhaka. Visitors page separates estimated unique visitors from page visits. |
| Canonical host contradicted redirects | Apex homepage redirected to www; live homepage, services and blog canonical tags and sitemap entries still pointed to the apex domain. | Shared origin normalization aligns metadata, structured data, robots and sitemap with https://www.aptechagency.com. [Google canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls). |
| Robots rules blocked public content | Live Disallow: /c and /p also matched /company, /compliance, /partners, /privacy-policy and /payment-policy. | Portal rules now use /c/, /p/ etc.; public content remains crawlable and admin sections stay excluded. |
| Duplicate homepage and account pages in sitemap | Live sitemap included /landing, /login and /register. /landing rendered the homepage with the root canonical. | /landing permanently redirects to /; account pages are omitted and receive noindex response headers. |
| Unreliable sitemap modification dates | Most live entries shared a generated deployment timestamp, rather than a verified content change date. | Static entries omit unknown lastmod; articles retain actual modification dates. Sitemap reads published articles at request time. [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap). |
| Repeated public meta descriptions | Live homepage and services used the same broad service list. Other section pages shared the same builder default. | Main sections now have distinct descriptions. Company, compliance, client documents and policies receive their own canonical metadata and respect the indexing setting. [Google description guidance](https://developers.google.com/search/docs/appearance/snippet). |

Homepage, services and blog returned HTTP 200 with index/follow metadata during the check. There was no observed site-wide noindex block. The live sitemap exposed six article URLs; that is not evidence that all six are indexed or receiving impressions.

## What the visitor report means

- The dashboard reports the current month, plus today's activity; the yearly country panel and lifetime website-visits card are removed.
- Daily unique visitors are estimates from distinct existing hashed network addresses. Shared networks can undercount people; events without a network hash can overcount. No raw IPs or invented visitor names are displayed.
- Page visits count loads/navigation. The old implementation recorded at most one public event per browser tab session, so the new page-visit series is not directly comparable with older data.
- Missing older visits cannot be reconstructed. A storage failure is displayed as unavailable rather than as a real zero.
- No new database schema is required; the existing LandingVisitorEvent migration must already be deployed.

## Remaining diagnosis after deployment

1. Submit https://www.aptechagency.com/sitemap.xml in the existing verified Search Console property. Inspect the homepage, /services and representative blog articles. Check Google's selected canonical and crawl/index status.
2. Compare the latest 28 days with the preceding 28 days by query, page, country and device: impressions, clicks, CTR and position. Low impressions, low CTR and visitor-tracking loss are different problems. [Google traffic diagnosis](https://developers.google.com/search/docs/monitor-debug/debugging-search-traffic-drops).
3. Review Core Web Vitals/Search Console field data before attributing traffic to speed. The HTTP response checks here are not an LCP/INP/CLS audit.
4. The service catalogue currently offers many services on one broad page. Consider substantive pages for the two or three services the agency most wants to sell, supported by real case studies, scope, process and buyer questions. Avoid mass-generated thin keyword pages.
5. Review the six existing articles against actual Search Console queries. Broad introductory titles alone do not show whether there is relevant search demand, ranking or conversion potential.

These fixes remove measurement and crawl inconsistencies. They do not establish that technical SEO was the sole cause of slow visitor growth, and they cannot guarantee ranking or traffic gains. Live authenticated analytics and post-deployment results still need verification.

## Validation

18 regression tests and TypeScript checks passed. The production build passed. Local production-server checks confirmed /landing returns 308 to /, /login sends noindex, /visitors redirects unauthenticated requests to login, robots avoids the broad /c and /p blocks, sitemap omits account/alias URLs, and /services renders its www canonical and distinct description. The database was not configured locally, so actual event persistence and authenticated report contents still need a live-environment check. Existing LandingPage lint errors were compared against HEAD and are unchanged; the new analytics and SEO files have no lint errors.
